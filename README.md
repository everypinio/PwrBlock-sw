# Powerblock

Powerblock is a USBTMC-controlled bench power supply with USB Power Delivery (USB-PD) input support, built on an STM32G0 microcontroller. It exposes a SCPI command interface over USBTMC or USB CDC for remote voltage/current control, measurement, protection, and calibration.

## Cloning

Third-party libraries are included in the project as submodules. To initialize them, run the following command when cloning the repository:

```bash
git clone --recurse-submodules https://github.com/everypinio/PwrBlock-sw.git
```

If the repository already exists locally and the submodules need to be updated, run:

```bash
git submodule update --init --recursive
```

## Building

Open the project in the container.

Build via the `CMake Tools` extension, the `Build` task in `Task Explorer`, or from the command line:

```bash
make build
```

Build configurations available:

- Debug (TMC mode) — build with debug symbols for a USBTMC device.
- Debug (CDC mode) — build with debug symbols for a CDC device (with extended WebUSB support).
- Release (TMC mode) — optimized release build for a USBTMC device.
- Release (CDC mode) — optimized release build for a CDC device (with extended WebUSB support).

## CI and releases

GitHub Actions builds the release firmware automatically inside the repository
Docker image on pushes to `main` or `master`, on pull requests, and on manual
workflow runs. The workflow builds both release presets:

- `release-tmc`
- `release-cdc`

Build artifacts are uploaded as `power_block-firmware` and include generated
`.elf`, `.hex`, `.bin`, and `.map` files.

To publish a GitHub Release, create and push a version tag:

```bash
git tag v0.1.0
git push origin v0.1.0
```

The tag workflow creates a release and attaches the firmware artifacts.

Flash the firmware to the board via the `Flash` task in `Task Explorer` or from the command line:

```bash
make flash
```

## Configuring

The main project configuration file is `/src/bsp/periph_setup/periph_setup.ioc`. The project is built using:

- CubeMX: 6.15.0
- CubeHAL: STM32Cube FW_G0 V1.6.2

Peripheral modifications can be made through it, keeping in mind the peripherals occupied by the `stm32_usbpd` library. Additional configuration (FreeRTOS, tinyUSB, TracerEMB) is located in `/src/config`. Occupied peripherals:

| Library    | Peripherals                           |
| ---------- | ------------------------------------- |
| UCPD       | TIM1, DMA1_CH3, DMA1_CH4              |
| TRACER_EMB | USART3 (PB0, PB2), DMA1_CH2 (TX only) |

After adding a peripheral in CubeMX and generating the project, run the `cube_after_gen` task or the following command:

```bash
make cube_after_gen
```

This is necessary to correctly format the sources and remove extra files generated by CubeMX.

## Usage

### USBCDC device

Any terminal program (`PuTTY`, `moserial`) will work to test the interface. The serial port speed configuration doesn't matter, since packets are sent at the maximum speed of the USB 2.0 device. The important setting is the line ending: `CR (only)`. Communication with the device is done by sending requests as SCPI commands, as described above.

### USBTMC device

The Python packages `pyvisa`, `pyvisa-py`, `pyusb` must be installed beforehand.

```bash
pip install pyvisa pyvisa-py pyusb
```

Sending commands and receiving data can be done from the `pyvisa-shell` console application; before starting work you need to get a list of devices:

```bash
Welcome to the VISA shell. Type help or ? to list commands.

(visa) list
( 0) USB0::0x1209::0x0002::0123456789ABCDEF::INSTR
```

Then open the corresponding port:

```bash
(visa) open 0
USB0::0x1209::0x0002::0123456789ABCDEF::INSTR has been opened.
You can talk to the device using "write", "read" or "query".
The default end of message is added to each message.
```

Queries are performed via the `query` command:

```bash
(open) query *IDN?
Response: EVERYPINIO,POWERBLOCK,0,0.1
```

Writing to the device is performed via the `write` command:

```bash
(open) write OUTPut ON
(open) query OUTPut?
Response: 1
```

An example script `./tools/usb_tmc_test.py` for working with an SCPI device via Python is also implemented. Running the test:

```bash
python tools/usb_tmc_test.py
```

### Permission issues on Linux

If needed, permissions on a block device of type `usbtmc` can be granted via the `udev` system. For a USBTMC device:

```bash
$ sudo echo 'SUBSYSTEMS=="usb", ATTRS{idVendor}=="1209", ATTRS{idProduct}=="0002", GROUP="plugdev", MODE="0666"' > /etc/udev/rules.d/100-usbtmc.rules
```

For a CDC device with WebUSB support (required for Chrome device-connection notifications to work correctly):

```bash
$ sudo echo 'SUBSYSTEMS=="usb", ATTRS{idVendor}=="1209", ATTRS{idProduct}=="0001", GROUP="plugdev", MODE="0666"' > /etc/udev/rules.d/100-usbtmc.rules
```

Reload the `udev` system without rebooting:

```bash
$ sudo udevadm control --reload-rules && sudo udevadm trigger
```
